# PRD: Task Priority App — v2 "ตัดสินใจทีละคู่"

สถานะ (2026-10-17): : ร่าง 1 · ต่อจาก MVP1 (docs/PRD.md) · การตัดสินใจของ MVP1 อยู่ใน docs/DEV_PLAN.md

## 1. ปัญหา

ผู้ใช้ MVP1 ต้องจัดลำดับงานใหม่**ทุกเช้า** แต่เมื่อมีงานหลายชิ้น การมองลิสต์ทั้งหมดพร้อมกันแล้วลากให้ถูกทำให้เกิด analysis paralysis ยิ่งงานเยอะยิ่งตัดสินใจไม่ได้ (หลักฐาน: ประสบการณ์ตรงของ Product Owner ซึ่งเป็นผู้ใช้เป้าหมาย ใช้แอปจัดลำดับรายวัน)

นอกจากนี้ผู้ใช้ไม่เห็นว่างานไหนมีกำหนดส่งเมื่อไร และแก้ชื่องานที่พิมพ์ผิดไม่ได้นอกจากลบแล้วเพิ่มใหม่ ซึ่งทำให้เสียลำดับ

ถ้าไม่แก้ ผู้ใช้จะเลิกจัดลำดับทุกเช้าและลิสต์จะกลายเป็นกองงานธรรมดา ซึ่งทำลายคุณค่าหลักของแอป

## 2. หลักการของ v2

> **ทุกเช้า ตัดสินใจทีละคู่ โดยแอปให้ข้อมูล ไม่ตัดสินแทน**

- MVP1 ตอบว่า "ใครจัด" = ผู้ใช้
- v2 ตอบว่า "จัดจากอะไร" = ผู้ใช้เห็นกำหนดส่ง และได้เทียบทีละ 2 ชิ้นแทนการมองทั้งลิสต์
- แอป**ไม่เคย**เปลี่ยนลำดับเองโดยที่ผู้ใช้ไม่ได้เป็นคนตอบ

ใช้ประโยคนี้ตัดสินทุกคำขอเพิ่มฟีเจอร์ระหว่างพัฒนา

## 3. เป้าหมาย

แอปไม่มี analytics (ข้อมูลอยู่ในเครื่องผู้ใช้) การวัดจึงมาจากการสังเกตและการจดเอง

| # | เป้าหมาย | วัดอย่างไร |
| --- | --- | --- |
| G1 | จัดลำดับงาน 8 ชิ้นได้โดยไม่ค้าง | ผู้ทดสอบจบ "ตรวจลำดับ" 1 รอบของงาน 8 ชิ้นภายใน 60 วินาที โดยไม่ถามว่าต้องทำอะไรต่อ |
| G2 | ใช้ได้จริงทุกวัน | PO ใช้ "ตรวจลำดับ" อย่างน้อย 4 วันต่อสัปดาห์ ต่อเนื่อง 2 สัปดาห์หลังปล่อย (จดเอง) |
| G3 | ข้อมูล MVP1 ไม่หาย | localStorage ของผู้ใช้ MVP1 ทุกชุดที่ทดสอบถูก migrate ครบ 100% ไม่มีงานถูกตีเป็น "เสียหาย" |
| G4 | ความผิดพลาดกู้คืนได้ | ทุกการกระทำในแอปย้อนกลับได้ด้วย Undo ภายใน 1 ขั้นตอน |

## 5. User Stories และ Acceptance Criteria

ผู้ใช้ในทุกข้อคือ "คนทำงานคนเดียวที่จัดลำดับงานของตัวเองทุกเช้า" เลข US ต่อจาก MVP1 (US-1 ถึง US-5) Acceptance criteria เขียนแบบ Given / When / Then เลข AC-{US}.{n} ใช้อ้างอิงในชื่อเทสต์

### F1 ตรวจลำดับ

**US-6 เริ่มตรวจลำดับ** — ฉันอยากเทียบงานทีละ 2 ชิ้น เพื่อไม่ต้องมองทั้งลิสต์พร้อมกัน

- AC-6.1 **Given** มีงาน todo 0 หรือ 1 ชิ้น \
**When** ดูปุ่ม "ตรวจลำดับ" \
**Then** ปุ่ม disabled และ aria-label บอกว่าต้องมีงานอย่างน้อย 2 ชิ้น

- AC-6.2 **Given** มีงาน todo ตั้งแต่ 2 ชิ้น \
**When** กด "ตรวจลำดับ" \
**Then** เข้าโหมดเต็มหน้า ลิสต์ ช่องเพิ่มงาน และส่วน "เสร็จวันนี้" ถูกซ่อน เห็นเฉพาะคำถาม การ์ด 2 ใบ ตัวนับ ปุ่ม "ข้าม" และ "ปิด"

- AC-6.3 **Given** งานในคู่มี deadline \
**When** การ์ดแสดง \
**Then** เห็นชื่องานและป้าย deadline รูปแบบเดียวกับในลิสต์

- AC-6.4 **Given** กด "ตรวจลำดับ" \
**When** โหมดเปิด \
**Then** focus อยู่ในโหมด \
และ \
**When** ปิดโหมด \
**Then** focus กลับไปที่ปุ่ม "ตรวจลำดับ"


**US-7 ตอบทีละคู่** — ฉันอยากตอบแค่ "อันไหนก่อน" แล้วให้ลิสต์ดีขึ้นทันที

- AC-7.1 **Given** งาน A, B, C, D (บนลงล่าง) \
**When** เริ่มโหมด \
**Then** คู่แรกคือ C (บน) กับ D (ล่าง)

- AC-7.2 **Given** คู่ C/D \
**When** เลือกการ์ดล่าง (D) \
**Then** ลิสต์เป็น A, B, D, C ทันทีทั้งใน state และ localStorage และคู่ถัดไปคือ B กับ D

- AC-7.3 **Given** คู่ C/D \
**When** เลือกการ์ดบน (C) หรือกด "ข้าม" \
**Then** ลำดับคงเดิม และคู่ถัดไปคือ B กับ C

- AC-7.4 **Given** งาน A, B, C, D โดย D สำคัญที่สุด \
**When** เลือก D ทุกคู่จนครบ 3 คำถาม \
**Then** ลิสต์เป็น D, A, B, C

- AC-7.5 **Given** ตอบคำถามสุดท้ายแล้ว \
**When** หน้าสรุปแสดง \
**Then** เห็นชื่องานที่อยู่บนสุดตอนนี้ พร้อมปุ่ม "อีกรอบ" และ "ปิด"

- AC-7.6 **Given** หน้าสรุป \
**When** กด "อีกรอบ" \
**Then** เริ่มรอบใหม่จากคู่ล่างสุดของลำดับปัจจุบัน ตัวนับเริ่มที่ 1 ใหม่


**US-8 ออกกลางคัน** — ฉันอยากหยุดเมื่อไรก็ได้โดยไม่เสียสิ่งที่ตอบไปแล้ว

- AC-8.1 **Given** ตอบไปแล้ว 2 คู่ มีการสลับ 1 ครั้ง \
**When** กด "ปิด" หรือ Escape \
**Then** โหมดปิดทันที ไม่มีหน้ายืนยัน และลิสต์แสดงลำดับที่มีการสลับนั้นแล้ว


**US-9 แก้คำตอบผิด** — ฉันอยากย้อนคำตอบที่เพิ่งเลือกผิด

- AC-9.1 **Given** เพิ่งเลือกการ์ดล่างในคู่ที่ 2 \
**When** กด ⌘Z หรือปุ่ม "เลิกทำ" ในโหมด \
**Then** การสลับถูกย้อน ลำดับกลับเหมือนก่อนตอบ และกลับมาที่คู่ที่ 2 ตัวนับ "คำถาม 2 จาก n-1"

- AC-9.2 **Given** ปิดโหมดหลังสลับไป 3 คู่ \
**When** กด ⌘Z 3 ครั้ง \
**Then** ลำดับย้อนกลับครั้งละ 1 คู่ จนเหมือนก่อนเข้าโหมด


**US-10 ใช้ได้ด้วยคีย์บอร์ด** — ฉันอยากตอบโดยไม่แตะเมาส์

- AC-10.1 **Given** อยู่ในโหมด \
**When** กด Tab ไล่ \
**Then** focus เรียง การ์ดบน → การ์ดล่าง → ข้าม → ปิด และไม่หลุดไปที่ลิสต์ที่ซ่อนอยู่

- AC-10.2 **Given** focus อยู่ที่การ์ดล่าง \
**When** กด Enter หรือ Space \
**Then** ผลเหมือนคลิกการ์ดล่าง (AC-7.2)

- AC-10.3 **Given** ตอบคู่หนึ่งเสร็จ \
**When** คู่ใหม่แสดง \
**Then** aria-live (polite) ประกาศคำถาม ชื่องานทั้งสอง และตัวนับ


**กรณีขอบของ F1**

- AC-F1.1 **Given** มีงาน todo 2 ชิ้นพอดี \
**When** เริ่มโหมด \
**Then** ถาม 1 คำถามแล้วไปหน้าสรุป

- AC-F1.3 **Given** อยู่ในโหมดและสลับไปแล้ว 1 คู่ \
**When** reload \
**Then** เปิดที่ลิสต์ปกติ ลำดับที่สลับแล้วยังอยู่ ไม่กลับเข้าโหมดเอง

### F2 Deadline

**US-11 ตั้งกำหนดส่ง** — ฉันอยากรู้ว่างานไหนต้องเสร็จเมื่อไร โดยไม่บังคับให้กรอกทุกงาน

- AC-11.1 **Given** ช่องเพิ่มงาน \
**When** พิมพ์ชื่อแล้วกด Enter \
**Then** เพิ่มงานได้เหมือน MVP1 โดยไม่ถูกถาม deadline

- AC-11.2 **Given** แถว todo ไม่มี deadline \
**When** กด "กำหนดส่ง: {title}" แล้วเลือกวันที่ \
**Then** `dueDate` ถูกบันทึกทันทีและป้ายแสดง

- AC-11.3 **Given** แถวมี deadline \
**When** กดปุ่มเดิมแล้วเลือก "ลบกำหนดส่ง" \
**Then** `dueDate` หายและป้ายหาย

- AC-11.4 **Given** เพิ่งตั้ง deadline \
**When** กด ⌘Z \
**Then** deadline หาย \
และ \
**When** กด Redo \
**Then** deadline กลับมา


**US-12 เห็นกำหนดส่ง** — ฉันอยากเห็นทันทีว่างานไหนใกล้หรือเลยกำหนด

- AC-12.1 **Given** วันนี้ 2026-10-17 และงาน `dueDate` 2026-10-15 \
**When** render \
**Then** ป้าย "เลยกำหนด 2 วัน" สไตล์เตือน

- AC-12.2 **Given** `dueDate` = วันนี้ \
**When** render \
**Then** ป้าย "วันนี้" สไตล์เน้น และ **Given** = พรุ่งนี้ **Then** "พรุ่งนี้"

- AC-12.3 **Given** `dueDate` 2026-10-24 \
**When** render \
**Then** "24 ต.ค." \
และ \
**Given** 2027-01-05 **Then** มีปีกำกับ

- AC-12.4 **Given** ป้ายทุกแบบ \
**When** วัด contrast ใน light และ dark mode \
**Then** ≥ 4.5:1 และทุกสถานะมีข้อความ ไม่ใช่สีอย่างเดียว

- AC-12.5 **Given** งานมี deadline \
**When** ทำเสร็จ \
**Then** แถวใน "เสร็จวันนี้" ไม่แสดงป้าย \
และ \
**When** ย้อนกลับ \
**Then** ป้ายกลับมา

- AC-12.6 **Given** เปิดแอปค้างข้ามเที่ยงคืน \
**When** ยังไม่มีการกระทำใด \
**Then** ป้ายยังเป็นของเมื่อวาน (ข้อจำกัดที่ยอมรับ) \
และ \
**When** มีการกระทำใด ๆ \
**Then** ป้ายคำนวณใหม่


**US-13 deadline ไม่แย่งจัดลำดับ** — ฉันอยากให้ลำดับเป็นของฉันเสมอ

- AC-13.1 **Given** งาน A, B, C \
**When** ตั้ง deadline เมื่อวานให้ C \
**Then** ลำดับยังเป็น A, B, C และ `order` ของทุกงานไม่เปลี่ยน

- AC-13.2 **Given** หน้าหลัก \
**When** มองหาตัวเลือกเรียง \
**Then** ไม่มีตัวเลือก "เรียงตาม deadline" ใน v2

### F3 แก้ชื่องาน

**US-14 แก้ในที่** — ฉันอยากแก้คำผิดโดยไม่ต้องลบแล้วเพิ่มใหม่

- AC-14.1 **Given** แถว todo \
**When** กด "แก้ชื่อ: {title}" หรือคลิกที่ชื่อโดยไม่ลาก \
**Then** ช่องแก้แทนที่ชื่อ มีข้อความเดิม focus ในช่อง เคอร์เซอร์ท้ายข้อความ

- AC-14.2 **Given** กำลังแก้ \
**When** พิมพ์ "  ซื้อนมสด  " แล้ว Enter หรือ blur \
**Then** ชื่อเป็น "ซื้อนมสด" และลำดับไม่เปลี่ยน

- AC-14.3 **Given** กำลังแก้ \
**When** กด Escape \
**Then** ชื่อเดิมคืนมา ไม่มีอะไรถูกบันทึก

- AC-14.4 **Given** กำลังแก้ \
**When** ลบข้อความจนว่างหรือเหลือแต่ช่องว่างแล้ว Enter \
**Then** ชื่อเดิมคืนมา

- AC-14.5 **Given** กำลังแก้ \
**When** พยายามลากแถวนั้น \
**Then** ไม่เริ่มลาก \
และ \
**When** กด ⌘Z ในช่อง \
**Then** เป็น undo ข้อความของเบราว์เซอร์ ไม่ใช่ของแอป

- AC-14.6 **Given** บันทึกชื่อใหม่แล้ว \
**When** กด ⌘Z นอกช่อง \
**Then** ชื่อเดิมกลับมา

- AC-14.7 **Given** แถวใน "เสร็จวันนี้" \
**When** ดูแถวหรือคลิกชื่อ \
**Then** ไม่มีปุ่มแก้ชื่อและไม่เข้าโหมดแก้

### F4 Undo / Redo

**US-15 เลิกทำได้ทุกอย่าง** — ฉันอยากกู้คืนความผิดพลาดโดยไม่ต้องคิดว่าเผลอทำอะไร

- AC-15.1 **Given** ลบ B จาก A, B, C \
**When** กด "เลิกทำ" \
**Then** B กลับมาตำแหน่งที่ 2 ไม่ใช่ท้ายลิสต์

- AC-15.2 **Given** ทำการกระทำแต่ละแบบ (เพิ่ม, ทำเสร็จ, ย้อนกลับ, ↑↓, ลาก, สลับจากตรวจลำดับ, แก้ชื่อ, ตั้ง/ลบ deadline) \
**When** กด ⌘Z \
**Then** state กลับเหมือนก่อนการกระทำนั้นทุกประการ รวม `completedAt`

- AC-15.3 **Given** ไม่มีประวัติ \
**When** ดูส่วนหัว \
**Then** ปุ่ม "เลิกทำ" และ "ทำซ้ำ" disabled

- AC-15.4 **Given** focus อยู่ในช่องพิมพ์ \
**When** กด ⌘Z \
**Then** แอปไม่ undo (ปล่อยให้เบราว์เซอร์จัดการ)

- AC-15.5 **Given** Undo แล้ว 1 ครั้ง \
**When** ทำการกระทำใหม่ \
**Then** Redo disabled

- AC-15.7 **Given** ทำ 60 การกระทำ \
**When** กด ⌘Z ซ้ำ \
**Then** ย้อนได้ 50 ครั้งแล้วปุ่ม disabled

- AC-15.8 **Given** ทำการกระทำแล้ว reload \
**When** กด ⌘Z \
**Then** ไม่มีอะไรย้อน (ประวัติอยู่แค่ใน session) และข้อมูลงานยังครบ

- AC-15.9 **Given** กด Undo หรือ Redo \
**When** เสร็จ \
**Then** localStorage ตรงกับ state ทันที

### F0 พื้นฐาน

**US-16 ผู้ใช้ MVP1 เปิด v2 แล้วทุกอย่างยังอยู่**

- AC-16.1 **Given** localStorage เป็น array รูปแบบ MVP1 ที่ถูกต้อง \
**When** เปิดแอป \
**Then** งานครบทุกชิ้น ลำดับเดิม และไม่มี key backup ถูกเขียน

- AC-16.2 **Given** เปิดแอปแล้ว migrate ในหน่วยความจำ \
**When** ยังไม่ทำอะไร \
**Then** localStorage ยังเป็นรูปแบบเดิม \
และ \
**When** ทำการกระทำครั้งแรก \
**Then** เขียนเป็น Store v2

- AC-16.3 **Given** งานมี `dueDate` "15/10/2026" (ผิดรูปแบบ) \
**When** โหลด \
**Then** งานยังอยู่โดยไม่มี `dueDate` และ backup ถูกเขียน

- AC-16.4 **Given** `schemaVersion` 3 \
**When** โหลด \

**US-17 อ่าน placeholder ออกใน light mode** — ฉันอยากเห็นคำแนะนำในช่องเพิ่มงานชัดเจนแม้ใช้โหมดสว่าง

## 6. Data Model

```ts
type Task = {
  id: string;
  title: string;
  order: number;
  status: "todo" | "done";
  createdAt: string;      // ISO
  completedAt?: string;   // ISO, บังคับเมื่อ status = done
  dueDate?: string;       // "YYYY-MM-DD" วันที่ท้องถิ่น ไม่มีเวลา ไม่มี timezone
};

type Store = {
  schemaVersion: 2;
  tasks: Task[];
};
```

- localStorage key เดิม `task-priority-app:tasks`
- v1 (MVP1) = `Task[]` ล้วน ๆ → migrate เป็น `Store` v2
- `dueDate` เป็นวันที่ปฏิทินของผู้ใช้ ไม่แปลง timezone (เทียบกับวันนี้ด้วยตรรกะเดียวกับ `isToday`)
- การ validate: `dueDate` ถ้ามีต้องตรง `^\d{4}-\d{2}-\d{2}$` และเป็นวันที่จริง
