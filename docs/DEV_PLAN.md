## การตัดสินใจสำคัญ
**Phase 0**
- Tailwind v4 แบบ CSS-first
- ล็อก React ไว้ที่ 18 เพราะ template ให้ 19 มา
- ใช้ oxlint ตามที่ template ให้มา
- jest-dom ใช้ entry `@testing-library/jest-dom/vitest` เพื่อให้ TypeScript รู้จัก matcher

**Phase 1** (ตาม Product Owner)
- **ข้อมูลเสียบางส่วน:**
  - เก็บงานที่ถูกต้อง ทิ้งเฉพาะชิ้นที่เสีย
  - ตัด field ที่ไม่รู้จักทิ้ง และนับว่าเป็นการทิ้งข้อมูล
  - งาน `done` ต้องมี `completedAt`
  - id ซ้ำให้เก็บชิ้นแรก
  - ทิ้งอะไรก็ตาม ต้อง backup string ดิบไว้ที่ `task-priority-app:tasks:corrupt-backup` (อันล่าสุดเขียนทับ)
- **ลำดับ:** เรียงเลข `order` ของงาน todo ใหม่เป็น 0..n-1 ตอนโหลด
- **งาน todo ที่มี `completedAt` ติดมา:** เก็บไว้ตามเดิม
- **ไม่เขียน localStorage ตอนเปิดแอป** เขียนเมื่อผู้ใช้เปลี่ยนอะไรครั้งแรก
- **ย้อนกลับงาน:** กลับไปท้ายลิสต์
- **ส่วน "เสร็จวันนี้":** แสดงเฉพาะงานที่เสร็จวันนี้ตามเวลาท้องถิ่น งานที่เสร็จวันก่อนไม่ถูกลบ
- **เทสต์:** รันด้วย `TZ=Asia/Bangkok` (P1-22 พิสูจน์แล้ว)

**Phase 2**
- **หน้าตา:**
  - h1 "จัดลำดับงาน"
  - หัวข้อ "งานที่ต้องทำ" แสดงเสมอ
  - `<title>Task Priority</title>`
  - ลบ favicon ของ Vite
- **ข้อความ:** ข้อความ UI ทั้งหมดอยู่ใน `src/lib/labels.ts`
- **ลากวาง:**
  - `handleDragEnd` แยกเป็นไฟล์ของตัวเอง เพราะกฎ lint `only-export-components`
  - listeners ผูกที่ drag handle เท่านั้น (P2-38 ตรวจ)
  - PointerSensor ระยะ 5px และ `closestCenter`
- **การลบ:** ลบทันที ไม่มีหน้าต่างยืนยัน

## ข้อจำกัดที่รู้อยู่
- หลังโหลด เลข `order` ในหน่วยความจำถูกเรียงใหม่แล้ว แต่ใน localStorage ยังเป็นเลขเดิมจนกว่าผู้ใช้จะเปลี่ยนอะไร ลำดับที่เห็นเหมือนกันทุกประการ
- jsdom ทดสอบการลากและการจัดลำดับด้วยคีย์บอร์ดของ dnd-kit ไม่ได้ ต้องตรวจเอง (M-01, M-02)
- P2-44 ตรวจ `index.html` แบบตรงตัวอักษร ถ้าเพิ่ม attribute ให้แท็ก `<html>` ข้อนี้จะ fail
