## สิ่งที่เทสต์อัตโนมัติไม่ครอบคลุม
jsdom ไม่มี layout จริง และ input เป็นแบบสังเคราะห์ **ทุกครั้งที่แก้ส่วนลากวาง** (`TaskItem`, `TaskList`, `cardPointerSensor`, `listCollisionDetection`, `handleDragEnd`) ต้องตรวจเองในเบราว์เซอร์อย่างน้อย:

| ข้อ | ทำไมเทสต์อัตโนมัติไม่พอ |
|---|---|
| M-01 ลากด้วยเมาส์ | เทสต์ครอบคลุมแค่ handler และจุดที่เริ่มลากได้ (P2-35..37, P2-50) ไม่ได้ครอบคลุมการเลื่อนจริง |
| M-02 คีย์บอร์ด | P2-50 ตรวจแค่ว่าเริ่มลากจาก ⠿ ส่วนการเลื่อนด้วยลูกศรต้องใช้ตำแหน่งจริงของการ์ด |
| M-03 กดปุ่มแล้วไม่ลาก | ระยะ 5px กับการขยับเมาส์จริง jsdom จำลองไม่ได้ |
| M-11 ปล่อยนอกลิสต์ | P3-05 ทดสอบฟังก์ชันด้วยกรอบจำลอง แต่กรอบจริงมาจาก layout |
| M-05 การปัดนิ้ว | ต้องใช้โทรศัพท์จริง |

ส่วน focus ring (M-08, M-14), screen reader (M-09) และ console (M-10) ก็ต้องดูในเบราว์เซอร์เช่นกัน

## จดไว้ ไม่แก้ใน MVP1
- placeholder "เพิ่มงานใหม่" ใน light mode contrast 2.6:1 ต่ำกว่า 4.5:1 (PO ตัดสินให้จดไว้ / dark mode ได้ 6.82:1)
- ปุ่ม disabled ใน light mode จางที่ 1.71:1 WCAG ยกเว้นปุ่ม disabled และยังมองเห็นได้
- ระหว่างยกงานด้วยคีย์บอร์ด สถานะ disabled ของ ↑↓ ยังเป็นของตำแหน่งเดิม หายไปหลังวาง
- หลังโหลด เลข `order` ในหน่วยความจำถูกเรียงใหม่แล้ว แต่ใน localStorage ยังเป็นเลขเดิมจนกว่าผู้ใช้จะเปลี่ยนอะไร ลำดับที่เห็นเหมือนกัน
- P2-44 ตรวจ `index.html` แบบตรงตัวอักษร ถ้าเพิ่ม attribute ให้ `<html>` ข้อนี้จะ fail
- ไม่รองรับการลากด้วยนิ้ว (เป็นการตัดสินใจ ไม่ใช่บั๊ก)
